=== TECHNOLOGY SELECTION GUIDELINES ===

Pick technologies based on both the project type AND the user's goals.
Do NOT blindly follow a single goal — consider the full picture:
  - What is the platform? (web, mobile, desktop, embedded, data/ML, game)
  - What are the user's priorities? (goals listed above)
  - What stack makes practical sense for this specific combination?

Hints by project type (not hard rules — override when project context demands it):
- Web APIs with low latency → .NET, Go, Java, Rust, Elixir
- Mobile apps → React Native, Flutter, Swift, Kotlin; backend: Node.js, Python, Go, .NET
- Data science / ML → Python (TensorFlow, PyTorch, scikit-learn); backend: FastAPI, Flask
- Real-time / WebSockets → Elixir, Go, Node.js, .NET SignalR
- Rapid prototypes / MVPs → Node.js, Python Django/FastAPI, Ruby on Rails
- Desktop apps → Electron, Tauri, .NET MAUI, Qt
- Games → Unity (C#), Godot (GDScript), Unreal (C++)
- IoT / Embedded → C, C++, Rust, MicroPython

Goals are priorities, not absolute filters. A "Performance" goal for a mobile app means recommending performant mobile frameworks (Flutter, native Swift/Kotlin), not forcing server-side languages.
