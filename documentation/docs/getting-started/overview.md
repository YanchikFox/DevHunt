# Platform Overview

> _If any detail here contradicts the code, trust the code — not this page._

DevHunt is a developer collaboration platform: project and task management, real-time chat, AI-assisted planning, showcase, badges, recommendations, and integrations — all served through a single Nginx gateway.

## Services

| Compose service        | Role                                    | Tech                      | Default host port |
| ---------------------- | --------------------------------------- | ------------------------- | ----------------- |
| `api-gateway`          | TLS termination, edge routing           | Nginx                     | 80 / 443          |
| `core-api`             | Business logic, SignalR hubs            | .NET 10 ASP.NET Core      | 7002              |
| `auth-service`         | JWT issuance, OAuth, TOTP 2FA           | .NET 10 ASP.NET Core      | 7001              |
| `frontend`             | Web UI, Next.js API proxy               | Next.js 16 / React 19     | 3000              |
| `ml-service`           | Recommendations, AI features            | Python / FastAPI          | internal          |
| `integration-gateway`  | Third-party integration routing         | —                         | internal          |
| `notification-service` | Push notifications                      | —                         | internal          |
| `db-migrator`          | One-shot EF Core migrations             | .NET 10 console           | exits after run   |
| `db`                   | Primary data store                      | PostgreSQL                | internal          |
| `message-broker`       | Async domain events                     | RabbitMQ                  | internal          |
| `cache-service`        | Caching, SignalR backplane, rate limits | Redis                     | internal          |
| `object-storage`       | File/image storage                      | SeaweedFS (S3-compatible) | internal          |

## Request path

The browser always talks to the frontend on port 3000 (dev) or through `api-gateway` on 443 (prod). The frontend proxies all backend traffic — the browser never holds a direct service URL.

`api-gateway` routing:

| Location                       | Upstream                          |
| ------------------------------ | --------------------------------- |
| `/api/auth/*`                  | `auth-service`                    |
| `/api/*`                       | `core-api`                        |
| `/chatHub`, `/notificationHub` | `core-api` with WebSocket upgrade |
| everything else                | `frontend`                        |

## Startup order

1. `db` starts
2. `db-migrator` connects, runs EF Core migrations, exits 0
3. `auth-service` and `core-api` start — both declare `db-migrator: { condition: service_completed_successfully }`
4. `frontend`, `ml-service`, and other services start independently
